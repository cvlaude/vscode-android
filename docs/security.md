# Runtime boundary

The Android app requests INTERNET and Termux's RUN_COMMAND permission. The latter requires the user's Android permission grant and lets the native launcher start the fixed `~/.local/bin/workspace` executable through Termux's foreground service. Bootstrap enables Termux's external-command setting. Other apps still need their own Android command permission. The WebView exposes only display scale and screen-cutout geometry through its native bridge. It disables file URL access and mixed content and restricts main navigation to localhost. Android backups are disabled and the saved launcher link is encrypted with Android Keystore. File import/export uses Android's document picker.

The runtime runs under Termux's Android application UID. That UID is the boundary protecting other apps' private data. Do not give Termux broad storage access, root, accessibility privileges, notification access, Android API bridges, SSH agent sockets, or personal-file mounts. This version uses PRoot's isolated mount mode but does not treat PRoot as a security boundary. Processes within Termux can potentially access the rest of that app's private files, including the runtime, pairing material and Codex login.

`accept all` is not enabled by this project. Codex starts with `workspace-write`, `on-request` approvals and restricted sandbox network access. Run `python3 /opt/workspace-install/runtime/codex/probe.py` on the actual device. It verifies a workspace write succeeds, a write to a disposable neighboring file fails, and a TCP connection fails. A failure leaves settings unchanged. No fallback adds `danger-full-access`, disables the sandbox, or silently changes the approval policy.

A successful probe is evidence for those three operations on that kernel and Codex version, not a proof against every escape. Codex's own escalation approvals remain subject to the user's choices. In particular, accepting an escalation can authorize operations beyond the default workspace boundary. For unattended work with broader permissions, use a separately isolated Android profile/runtime or an independently powered host with a verified sandbox. On the tested Android 15 ARM64 device, the default sandbox exits 182 without output for all three probe commands, including the allowed workspace write. This is a failed sandbox initialization, not evidence of enforcement. Automatic command execution remains unavailable under that profile.

# Transfer boundary

Pairing uses a random 256-bit secret. LAN requests carry an HMAC proof over method, exact path, nonce and request-body hash. Proofs expire after five minutes and cannot be reused within the running server. File contents and manifest metadata use AES-256-GCM with distinct authenticated labels and random nonces. PBKDF2-SHA256 derives transfer keys with a random salt and 250,000 iterations. SHA-256 verifies every decompressed chunk and reconstructed file. LAN HTTP still exposes request timing and content hashes; use a trusted local link or a separate authenticated VPN for remote mirroring. This repository does not provision a relay or public internet listener.

The companion writes and fsyncs chunks before publishing a received manifest. A resumed transfer reuses verified chunks. Only full verified snapshots become latest. The initial seed, runtime downloads, extension packages and Git history can be large; seed locally. Subsequent source and session changes reuse 16 KB chunks. An insertion shifts following fixed-size chunks, so this is not a byte-optimal rolling-delta protocol. Later Git snapshots retain existing packs and add only objects not reachable from the previous captured roots. Missing prior objects can require a new full pack. Capture and restore stream packs through disk rather than buffering the entire history in memory.

Restore accepts only an empty destination, verifies file hashes, rejects traversal/ADS/Windows aliases/case collisions, and refuses symlinks. It restores a deliberately limited Git metadata set: pack, refs, HEAD, index and Desktop SCM queue. Hooks, remotes with embedded credentials, global Git configuration and OS credential stores are excluded. Workspace trust is disabled in the Android profile at the user's request. Project tasks and extension code can execute within Termux.

Snapshots include tracked and nonignored files, with an additional filename exclusion for common credential files in the working tree. Git history and staged blobs retain tracked content, including any previously committed secrets. This is not a secret-content scanner. Review your repository, history and `.gitignore` before exporting. Selected Codex rollouts can contain sensitive code and conversation content and use the same encryption as source files. The Codex login cache is exported only through a separate explicit command. Private chunks are plaintext in each device's private application-data store; the network and handoff files are encrypted.

# Recovery limits

Native Syncthing caches are receive-only and use 30-day trashcan versioning. Opening a project copies it to a separate editable folder. Code copies have a files-only baseline and do not pretend to contain Git history. Full copies require Git integrity checks and omit hooks, remote configuration and linked files. Intentional build omissions are marked skip-worktree only in the copied index.

Workspace holds an authenticated localhost lifetime socket to the native runtime supervisor. Closing the app ends that connection, stops its process group and synchronization, then ends Termux. The socket is separate from the companion and does not accept commands. Hiding Termux notifications changes Android's notification permission only; its foreground-service lifecycle remains in use.

The source's Git HEAD, refs, index and queue are checked before and after capture, and each working file is checked for modification during its read. This is a crash-recoverable handoff, not an operating-system-wide atomic snapshot. Avoid capture during Git commits or queue edits. The companion refuses known Git/queue locks. A PC cutoff can lose work that was not yet saved or transmitted. The phone shows the completed snapshot time, so verify it before disconnecting.

The Windows return merge requires the original common base. It preserves incoming conflicts and prior file bytes in the recovery directory. It does not merge Git refs, staged changes, Desktop SCM queues, Codex databases, token refreshes, or editor layout state into a live desktop session. The complete incoming repository can instead be restored alongside it for review. No automatic push or commit is performed.
